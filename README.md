# QNX屏幕绘制示例项目

[Switch to English README](README_EN.md)

## 项目简介

这是一个在QNX系统中使用screen库进行屏幕绘制的示例项目。该项目演示了如何在QNX和Android双系统环境下，通过切换到正确的display设备，成功在QNX系统中显示图形内容。

## 背景故事

在QNX和Android双系统环境中，默认显示的是Android界面。网上有大量资料介绍使用QNX的screen库来在QNX系统中绘制屏幕，但很多开发者按照教程操作却无法成功显示，甚至直接使用官方示例代码编译运行也不行。

作者经过长时间的探索和调试，最终发现问题的根源在于系统中存在多个display设备。默认情况下，应用程序会使用第0个display，但在双系统环境下，这个默认display可能无法正常显示内容。解决方法是将应用程序切换到另一个可用的display设备上。

本示例代码展示了如何先获取系统中的所有display设备，然后将应用程序切换到指定的display（本示例中使用第1个display），最后使用screen库绘制丰富的图形内容。

## 功能说明

本示例代码实现了以下功能：

1. 使用screen库创建屏幕上下文和窗口
2. 获取系统中所有可用的display设备数量
3. 将应用程序切换到指定的display设备（默认使用第1个display）
4. 创建窗口缓冲区并获取相关信息
5. 绘制丰富的图形内容，包括：
   - 渐变背景（具有颜色切换动画效果）
   - 中心棋盘格矩形（具有移动动画效果）
   - 彩色边框
   - 对角线（具有偏移动画效果）
   - 多个随机位置的彩色圆点
   - 像素艺术风格的"HELLO QNX"文本（具有移动动画效果）
   - 分辨率和帧计数信息显示
6. 显示绘制内容并进入动画循环

## 编译方法

### 前提条件

- 已安装QNX SDP开发环境
- 已配置好交叉编译工具链

### 编译步骤

1. 确保当前目录下有`CMakeLists.txt`文件
2. 创建构建目录：
   ```bash
   mkdir build
   cd build
   ```
3. 运行CMake生成Makefile：
   ```bash
   cmake ..
   ```
4. 编译项目：
   ```bash
   make
   ```
5. 编译成功后，会生成可执行文件`qnx_display`

## 使用说明

1. 在QNX系统上运行编译好的可执行文件：
   ```bash
   ./qnx_display
   ```

2. 观察屏幕上是否显示了绘制的图形内容

3. 如果没有显示内容，可能需要修改代码中的`DEFAULT_DISPLAY_INDEX`宏定义，尝试使用不同的display设备：
   ```cpp
   // 默认显示设备索引 (0-based)
   #define DEFAULT_DISPLAY_INDEX 1  // 尝试修改为0、2等其他值
   ```

4. 重新编译并运行，直到找到可以正常显示的display设备

## 注意事项

1. 本示例在双系统环境下，默认的第0个display无法正常显示，切换到第1个display可以正常显示。但不同的系统环境可能有所不同，需要根据实际情况进行调整。

2. 可以通过观察程序输出的"Display count: X"信息，了解系统中可用的display设备数量，然后尝试使用0到X-1之间的索引值。

3. 代码中包含500帧的动画循环，运行结束后会自动退出，无需手动终止。

4. 本示例仅用于演示目的，实际应用中应该添加适当的事件处理和资源释放机制。

## 代码结构

- `main.cpp`：主程序文件，包含所有的screen库调用和动画循环逻辑
- `draw_graphics.h`：图形绘制功能的头文件，定义了各种图形绘制函数的接口
- `draw_graphics.cpp`：图形绘制功能的实现文件，包含各种图形绘制函数的具体实现
- `CMakeLists.txt`：CMake构建配置文件
